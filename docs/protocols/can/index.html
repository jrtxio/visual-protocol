CAN 协议学习

控制器局域网络 — ISO 11898 — 从总线仲裁到 CAN FD

CAN 协议基础概念

CAN（Controller Area Network）是 ISO 11898 定义的串行通信协议，为汽车电子提供了高可靠、实时的数据通信基础。

核心概念详解

🚌 总线拓扑

多点连接，所有节点共享同一通信介质。任何节点都可以发送和接收报文，所有消息都是广播形式。总线两端需要终端电阻（120Ω）防止信号反射。

⚡ 仲裁机制

CSMA/CD+AMP（载波侦听多路访问/冲突检测+仲裁优先级）。通过"线与"机制实现非破坏性仲裁：ID 值越小的报文优先级越高，发送隐性位(1)的节点检测到显性位(0)则自动退出。

📋 四种帧类型

数据帧（携带数据的标准帧）、远程帧（请求数据）、错误帧（检测到错误时发送，含错误标志+错误定界符）、过载帧（请求延迟下一帧的传输）。

🚀 CAN FD

Flexible Data-rate，数据段速率最高 8 Mbps（仲裁段保持原速率），数据长度从 8 字节扩展至 64 字节。新增 FDF、BRS、ESI 控制位，向下兼容 CAN 2.0。

📡 CAN XL

ISO 11898-1:2024 最新演进，数据段最大 2048 字节，10 Mbps 以上波特率，引入简单 MAC/LLC 子层概念，可与以太网协议栈桥接。尚处产业化早期。

⏱️ 位时序

标称位时间分为同步段(SyncSeg)、传播段(PropSeg)、相位缓冲段1(PhaseSeg1)和相位缓冲段2(PhaseSeg2)。采样点通常在 PhaseSeg1 和 PhaseSeg2 之间，位时序参数决定波特率。

🛡️ 错误处理

五种错误类型：位错误、填充错误、CRC 错误、格式错误、ACK 错误。节点有三种状态：错误主动(Error Active，TEC<128)、错误被动(Error Passive，TEC≥128)、总线关闭(Bus Off，TEC≥256)。

🚗 应用场景

动力系统 CAN（发动机、变速箱）、车身 CAN（车门、车窗、灯光）、底盘 CAN（ABS、ESP）、诊断 CAN（OBD 接口）、CAN FD 用于 ADAS 传感器数据传输。

协议栈结构

CAN 协议遵循简化的四层模型，各层协同确保报文从应用层可靠传输到物理总线。

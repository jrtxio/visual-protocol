DoIP 协议学习

基于 IP 的诊断 — ISO 13400 — 从车辆发现到远程诊断

DoIP 协议基础概念

DoIP（Diagnosis over Internet Protocol）是 ISO 13400 定义的车载以太网诊断协议，通过 TCP/IP 承载 UDS 诊断服务，实现高速远程诊断和 OTA 更新。

核心概念详解

🌐 网络角色

5 种角色：DoIP 节点（外部 Tester）、DoIP 网关（车辆侧协议转换）、外部测试设备（运行诊断软件）、车辆节点（车内 ECU）、车内 ECU（被诊断目标）。网关是以太网和车内总线的桥梁。

📈 vs CAN 诊断

带宽从 CAN 的 500kbps 跃升至 100Mbps，支持远程诊断（通过互联网接入）、多路并发诊断会话、大文件 OTA 固件更新。CAN 诊断受限于物理连接和带宽，DoIP 打破了这些限制。

🔗 TCP/IP 传输

TCP 端口 13400 用于大数据量诊断通信（可靠传输），UDP 端口 13400 用于车辆发现和节点公告（无连接、低延迟）。TCP 确保诊断消息可靠到达，UDP 用于广播发现。

📋 协议版本

当前主流版本 ISO 13400-2:2019，协议版本号 0x02。相比 0x01 版本增加了安全认证、改进了路由激活流程、支持更大负载长度。新旧版本通过逆版本号区分。

🔍 车辆发现

Tester 通过 UDP 广播发送车辆识别请求（Payload Type 0x0001），车辆节点响应车辆声明消息（0x0004），包含 VIN、EID（Entity ID）、GID（Group ID）和逻辑地址等关键信息。

🔑 路由激活

Tester 通过路由激活请求（0x0005）与目标 ECU 建立诊断路由。网关验证 Tester 的源地址后返回激活响应（0x0006），支持认证激活类型（如 0x01 Default、0x0E 中央安全）。

💓 存活检查

网关周期性发送存活检查请求（0x0007），Tester 必须在超时时间内响应存活检查响应（0x0008）。超时未响应则网关断开 TCP 连接，释放诊断资源。

🔧 诊断通信

激活路由后，Tester 通过诊断消息（0x8001）发送 UDS 请求（如 ReadDataByIdentifier 0x22），网关将 DoIP 消息解封装后通过车内总线转发至目标 ECU，再将响应封装回 DoIP 返回。

协议栈结构

DoIP 协议栈从上到下共 5 层，UDS 诊断服务通过 DoIP 封装后经 TCP/IP 在以太网上传输。

UDS 诊断服务
ISO 14229 诊断请求/响应
DoIP 协议
ISO 13400 消息封装/解封
TCP / UDP
传输层 (端口 13400)
IPv4
网络层寻址与路由
Ethernet
物理链路 (100BASE-T1)

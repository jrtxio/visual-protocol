TCP 协议学习

Transmission Control Protocol — 从连接建立到可靠传输

TCP 协议基础概念

TCP（Transmission Control Protocol，传输控制协议）是面向连接的可靠传输层协议，为应用层提供可靠的字节流传输服务，保证数据按序到达、无丢失、无重复。

核心概念详解

🔗 面向连接

TCP 在数据传输前必须建立连接（三次握手），传输后释放连接（四次挥手）。提供可靠的字节流传输服务，保证数据按序到达、无丢失、无重复。

🤝 三次握手

建立连接的三步：① Client 发送 SYN（seq=x）→ ② Server 回复 SYN+ACK（seq=y, ack=x+1）→ ③ Client 发送 ACK（ack=y+1）。确保双方都具备收发能力。

👋 四次挥手

断开连接的四步：① 主动方发送 FIN → ② 被动方回复 ACK → ③ 被动方发送 FIN → ④ 主动方回复 ACK。双方各发一个 FIN 确认关闭，确保数据全部传输完毕。

🪟 滑动窗口

TCP 使用滑动窗口机制实现流量控制。发送方维护一个发送窗口，只能发送窗口内的数据；接收方通过 ACK 中的 Window 字段通知发送方可用的接收缓冲区大小。

🚦 拥塞控制

四个核心算法：慢启动（指数增长 cwnd）、拥塞避免（线性增长 cwnd）、快重传（收到 3 个重复 ACK 立即重传）、快恢复（cwnd 减半而非重置为 1）。防止网络过载。

🔢 序列号与确认

TCP 为每个字节分配序列号（Sequence Number），接收方通过确认号（Acknowledgment Number）告知发送方已收到的字节位置。实现可靠传输和按序交付。

⏱️ 超时重传

发送方启动定时器等待 ACK，超时未收到则重传数据段。RTO（Retransmission Timeout）基于 RTT（Round-Trip Time）动态计算，适应不同网络延迟。

📊 流量控制

接收方通过 TCP 头部的 Window 字段通告自己的接收缓冲区剩余空间。发送方据此控制发送速率，防止接收方缓冲区溢出。Window=0 时触发零窗口探测机制。

⚡ 与 UDP 对比

TCP 面向连接、可靠传输、有序交付、有流量/拥塞控制，适合文件传输/Web/邮件等；UDP 无连接、尽力传输、无序交付、无拥塞控制，适合实时音视频/DNS/DDS 等低延迟场景。

🏗️ 协议栈结构

在车载场景中 TCP 的位置：应用层（诊断 UDS 等）→ DoIP（诊断传输）→ TCP → IP → Ethernet → 物理链路。DoIP 使用 TCP 传输大数据量的诊断数据。

协议栈结构

TCP 位于传输层，为上层应用协议提供可靠的字节流传输，在车载诊断场景中承载 DoIP 等协议。

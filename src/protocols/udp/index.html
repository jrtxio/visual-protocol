UDP 协议学习

User Datagram Protocol — 无连接、轻量、高效的数据报传输

UDP 协议基础概念

UDP（User Datagram Protocol，用户数据报协议）是传输层最轻量的协议，以极低的头部开销提供无连接的数据报传输服务，广泛用于实时通信、DNS 查询、音视频流和车载网络。

核心概念详解

无连接传输

UDP 不需要建立连接即可发送数据。每个数据报独立传输，不保证到达、不保证顺序、不保证不重复。开销极低（仅 8 字节头部），适合对实时性要求高、可容忍少量丢包的应用。

数据报模型

UDP 保留应用层数据的边界，每次发送对应一个完整的数据报。不同于 TCP 的字节流模型，UDP 的消息边界完整保留，接收方收到的就是发送方发出的完整消息。

与 TCP 对比

UDP 无连接/不可靠/无序/无流量控制/无拥塞控制/8字节头部；TCP 面向连接/可靠/有序/流量控制/拥塞控制/20+字节头部。UDP 延迟低、吞吐高，适合实时场景。

多播与广播

UDP 支持一对多通信：多播（Multicast，组地址 224.0.0.0-239.255.255.255）和广播（Broadcast，255.255.255.255）。TCP 只支持点对点。DDS 的发现协议使用 UDP 多播。

DNS 查询

DNS 是 UDP 最典型的应用之一。DNS 查询通常使用 UDP 53 端口，因为查询-响应模式简单、数据量小（通常 <512 字节）。只有区域传输（Zone Transfer）才使用 TCP。

在车载中的应用

SOME/IP 使用 UDP 传输事件通知和周期性数据；DDS 使用 UDP 多播进行节点发现和数据分发；TSN（Time-Sensitive Networking）基于 UDP 实现确定性传输。

校验和

UDP 校验和是可选的（IPv4 中可以设为 0 表示不校验），但 IPv6 中强制使用。校验范围覆盖伪头部（源/目的 IP、协议号、UDP 长度）+ UDP 头部 + 数据。

UDP-Lite

UDP-Lite（RFC 3828）是 UDP 的变体，允许只校验数据报的部分内容。适合音视频流媒体场景——部分数据损坏时仍可将未损坏的部分传递给应用层。

QUIC 协议

QUIC 基于 UDP 实现了类似 TCP 的可靠传输，同时支持多路复用和 0-RTT 连接建立。HTTP/3 使用 QUIC 作为传输层。展示了 UDP 作为"构建基座"的灵活性。

协议栈结构

在车载场景中的位置：应用层（SOME/IP 事件 / DDS / TSN）→ UDP → IP → Ethernet → 物理链路。UDP 位于传输层，为上层应用提供端口复用和可选校验功能。
